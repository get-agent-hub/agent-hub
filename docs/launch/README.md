Prepared 2026-11-06 for the beta.2 candidate and the user-demand review. The artifact manifest records the frozen source revision. These are review drafts, not published posts, sent invitations or product promises for a new release.

- [Readiness](READINESS.md): passed checks and explicit remaining release gates.
- [Codex → DSH trial](REAL_CLIENT_TRIAL.md): the maintainer’s real-client evidence.
- [Show HN](SHOW_HN.md): title, submission destination and first maker comment.
- [Product Hunt](PRODUCT_HUNT.md): tagline, description and maker comment.
- [Demo storyboard](DEMO_STORYBOARD.md): an 80-second recording of the actual interface.
- [Five-user pilot](PILOT.md): recruitment criteria, observation script, two-week follow-up and decision gate.
- [Pilot log](PILOT_LOG_TEMPLATE.md): minimal local records without transcripts or credentials.

Before using these drafts, verify the release linked from the landing page includes archive background updates and Continue in…. The existing v0.1.0-beta.1 release archive predates those changes. Do not direct visitors to that archive while demonstrating newer behavior. The source-install route is documented, but requires Node.js 22.13+, npm and a build/install step; show this cost plainly.

Supported scope: Claude Code, Codex CLI and DeepSeek Harness; supported local saved files; local archive/search; selected-source background capture; reviewed context excerpts for a new chat. Shared MCP/skills/instruction delivery and optional project memory exist, but the launch headline tests retrieval and useful continuation. No exact active-session transfer, automatic synchronization of every data type, cloud-history recovery, new provider quota or extra model supplied by Hub.

## Existing launch guidance

Use the already reviewed sources from [USER_DEMAND.md](../proposals/simple-hub/USER_DEMAND.md):

- [Show HN guidelines](https://news.ycombinator.com/showhn.html): people must be able to try the working product; the landing page alone is insufficient. Keep entry barriers clear, answer questions and do not solicit votes.
- [Product Hunt launch guide](https://help.producthunt.com/en/articles/17350772-launch-guide): use a working product and a concrete explanation; treat feedback as the purpose of this small launch.

The current draft text avoids unsupported comparative claims and fabricated demand. A launch rank, downloads or stars do not replace successful tasks and unprompted return use.
