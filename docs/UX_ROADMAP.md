# Usability completion plan

Work is ordered by user impact. Verification uses isolated profiles; production settings and private research stay untouched. Website publication remains maintainer-managed.

## P0 — predictable writes and truthful readiness

- [x] MCP import previews by default, requires exact reviewed application and has no implicit source preference.
- [x] Setup offers explicit interactive confirmation without copying runtime paths.
- [x] CLI/UI distinguish configuration, MCP connection evidence and observed memory activity.

## P1 — usable memory and conflict resolution

- [x] Available default memory scope and actual record counts.
- [x] Server-allowlisted registered project selection with scope-bound previews.
- [x] Per-item direction: accept a selected client into Hub or deliver Hub to that client.

## P2 — reversible operations

- [x] Project disconnect preserves knowledge and unrelated notes.
- [x] Guarded workflow undo independent of the first-baseline reset.

## P3 — installation and capability discovery

- [x] Packaged installation survives removal of the source checkout.
- [x] Help advertises supported actions only.
- [x] English docs, locale data, source archive and minimum-runtime/package/HTTP checks.

## Remaining manual verification

- [ ] Visual review in a dedicated authorized browser window. Automated HTTP/service tests cover functional UI behavior; a rendered browser pass remains separate.
- [ ] Maintainer working trial in real client sessions to assess memory retrieval and useful semantic capture. An observed checkpoint alone does not prove useful learning.
